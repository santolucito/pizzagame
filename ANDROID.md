# Pizza Rush on Google Play

The Android app is the same game wrapped with [Capacitor](https://capacitorjs.com). Every game file ships
inside the app, so it works offline and needs no server. App ID: `io.github.santolucito.pizzarush`
(permanent once uploaded to Play).

| Piece | Where |
| --- | --- |
| Android project | `android/` (generated by Capacitor, committed) |
| Copy the game into the app | `npm run android:sync` |
| Build in the cloud | `.github/workflows/android.yml` |
| Privacy policy | `privacy.html`, live at https://santolucito.github.io/pizzagame/privacy.html |
| Icon source | `assets/icon-only.png` (regenerate with `npx capacitor-assets generate --android`) |

After changing the game, nothing extra is needed: the workflow copies the latest files every build.

## 1. Make an upload key (once)

You need Java for `keytool`. Install it with `brew install --cask temurin`, then:

```sh
keytool -genkeypair -v -keystore ~/pizza-rush-upload.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

Keep the `.jks` file and its password somewhere safe, outside the repo. Google holds the real signing key
(Play App Signing), so a lost upload key can be reset through Play support, but it is slow.

## 2. Give the key to GitHub Actions (once)

```sh
base64 -i ~/pizza-rush-upload.jks | gh secret set ANDROID_KEYSTORE_BASE64
gh secret set ANDROID_KEYSTORE_PASSWORD
gh secret set ANDROID_KEY_ALIAS --body upload
gh secret set ANDROID_KEY_PASSWORD
```

## 3. Build

Push, then on GitHub open **Actions → Build Android app → Run workflow**, or:

```sh
gh workflow run android.yml && gh run watch
gh run download --name pizza-rush-android-<run number>
```

The download holds `app-release.aab` (for Play) and `app-debug.apk` (install it on a phone to try the game:
copy it over and open it, allowing installs from unknown sources). Each run gets a higher version code
automatically.

## 4. Play Console

1. Sign up at https://play.google.com/console ($25 once, plus ID verification, which can take a few days).
2. **Create app**: name "Pizza Rush" (or something more distinctive), Game, Free.
3. **Testing → Internal testing**: create a release and upload `app-release.aab`. Accept Play App Signing.
4. **App content** (left menu, "Policy"):
   - Privacy policy: `https://santolucito.github.io/pizzagame/privacy.html`
   - Ads: No.
   - Content rating: fill in the questionnaire (no violence, no chat, no purchases); expect "Everyone".
   - Target audience: pick the ages you want. Choosing ages under 13 puts the app under the
     **Families Policy**, which this game already fits (no ads, no data, no links out).
   - Data safety: "No data collected" and "No data shared".
   - Government app / financial features / health: No.
5. **Store listing**: short description (80 chars), full description, 512×512 icon (`icons/icon-512.png`),
   a 1024×500 feature graphic, and at least 2 phone screenshots (tablet screenshots are needed if you want
   the "designed for tablets" badge).
6. **Closed testing**: personal developer accounts made after November 2023 must run a closed test with at
   least 12 testers who stay opted in for 14 days before Production unlocks. Add testers by email, share the
   opt-in link, and wait out the 14 days.
7. **Production**: promote the tested release and send it for review (usually a few days, longer for
   apps aimed at children).

## Updating the app later

Change the game, push, run the workflow, and upload the new `.aab` to a new release in Play Console.
